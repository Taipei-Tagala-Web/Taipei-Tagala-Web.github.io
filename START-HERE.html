台北大加蚋扶輪社官網｜24 小時建置操作手冊

從解壓縮檔案到發布上 GitHub。測試站帳號 Taipei-Tagala-Web。

  1. 放檔案並確認結構（15 分）
  2. 環境準備（30 分）
  3. 建 repo 並讓網站先活著（20 分）
  4. 用 Claude Code 生成網站（主要工作）
  5. 上線前 QA（90 分）
  6. 發布與確認（30 分）
  7. 移交給正式站（之後才做）
  8. 疑難排解
  9. 待確認清單

24 小時時程建議

第 1 小時步驟 0–1放檔案、裝 git 與 gh、登入
第 2 小時步驟 2建 repo、開 Pages、確認「建置中」頁面能開
第 3–5 小時步驟 3.1只做中文首頁，來回修到滿意 ← 關鍵關卡
第 6–8 小時步驟 3.2中文版其餘四頁
第 9–12 小時步驟 3.3英文版與日文版共十頁
休息睡覺。QA 要用清醒的眼睛做
第 13–15 小時步驟 4QA 與修正
第 16–17 小時步驟 5發布、手機實機測試
剩餘緩衝。一定會用到

唯一的硬性關卡：第 5 小時結束前，中文首頁必須拍板。沒拍板就往下做，等於用未定的設計生成 15 個檔案。到時間還在改，就先接受一個「夠好」的版本繼續走。

0放檔案並確認結構

把下載的壓縮檔解開，裡面的內容全部複製到 C:\Tagala-Web\。

最常見的錯誤：多包了一層資料夾。你要的是 C:\Tagala-Web\assets\，不是 C:\Tagala-Web\tagala-starter\assets\。

複製完成後，C:\Tagala-Web\ 裡應該有這些：

C:\Tagala-Web\
├─ START-HERE.html        ← 這份文件（操作手冊）
├─ README.md              技術備註與待確認事項
├─ CLAUDE.md              專案規範，Claude Code 每次都會讀
├─ index.html             語系偵測轉址（已寫好，勿改）
├─ robots.txt             測試站擋搜尋引擎
├─ .nojekyll              空檔案，避免檔案被忽略
├─ assets\
│  ├─ css\tokens.css      設計 tokens
│  ├─ logo\               社徽 8 個 + favicon 4 個
│  ├─ brand\club-flag.webp
│  └─ events\             16 個活動 banner
├─ content\
│  ├─ site.json           社資訊、例會、導覽、UI 文案
│  ├─ events.json         8 場活動
│  └─ service.json        服務軌跡、社旗意象、數據卡
└─ tools\check-i18n.py    三語系完整性檢查

看不到 .nojekyll？Windows 預設隱藏開頭是點的檔案。檔案總管 → 檢視 → 勾「隱藏的項目」。如果解壓縮後真的沒有，在資料夾裡新增一個空的文字檔，命名為 .nojekyll（含開頭的點、不要副檔名）。

1環境準備

要裝的是兩個不同的程式。git 是版本控制程式本身，負責 commit 和 push，離線也能用。gh 是 GitHub 官方命令列工具，負責跟 GitHub 網站互動（建 repo、登入授權）。先裝 git，再裝 gh——順序有意義，gh 登入過程中有一個選項要用到 git。

1.1 安裝 Git

開 PowerShell（開始選單搜尋 PowerShell）：

winget install --id Git.Git -e

裝完把 PowerShell 關掉重開，否則新的 PATH 不會生效，你會看到「無法辨識 git 詞彙」的錯誤。重開後驗證：

git --version

看到類似 git version 2.4x.x.windows.1 就可以了。

如果 winget 失敗，改用官網安裝檔 https://git-scm.com/download/win，下載後一路按預設值下一步，不用改任何選項。

1.2 安裝 GitHub CLI

winget install --id GitHub.cli

同樣關掉 PowerShell 重開，然後驗證：

gh --version

1.3 Windows 專用的兩項 git 設定

git config --global core.longpaths true
git config --global core.autocrlf true

第一行避免路徑過長錯誤。第二行處理 Windows 與 Linux 的換行符差異——不設定的話，git 會顯示整個檔案都被改過，你就看不出真正改了什麼。

1.4 設定身分

git config --global user.name "Taipei-Tagala-Web"
git config --global user.email "tagala.web@gmail.com"

確認四項設定都進去了：

git config --global --list

應該看到 core.longpaths、core.autocrlf、user.name、user.email 四行。

1.5 登入 GitHub

gh auth login

依序選：GitHub.com → HTTPS → Y（用 gh 認證 git）→ Login with a web browser。畫面顯示一組八位數代碼，按 Enter 開瀏覽器，貼上代碼授權。

要用 tagala.web@gmail.com 那個帳號登入（Taipei-Tagala-Web），不是財務長的帳號。登入前先確認瀏覽器目前是哪個 GitHub 帳號，必要時先登出。

gh auth status

看到 Logged in to github.com account Taipei-Tagala-Web 就對了。

2建 repo 並讓網站先活著

repo 名稱只能是 Taipei-Tagala-Web.github.io。取別的名字，網站會被放在子目錄，/assets/... 這類絕對路徑會全部 404，你會在第二天遇到一整批莫名其妙的破圖。

2.1 建立並推上去

在 PowerShell 裡：

cd C:\Tagala-Web
git init
git add .
git commit -m "初始版本：素材、內容資料與專案規範"
gh repo create Taipei-Tagala-Web.github.io --public --source=. --push

repo 必須是 --public，免費帳號的 GitHub Pages 只支援公開 repo。

2.2 開啟 GitHub Pages

瀏覽器開 https://github.com/Taipei-Tagala-Web/Taipei-Tagala-Web.github.io

  1. 上方 Settings
  2. 左側 Pages
  3. Source 選 Deploy from a branch
  4. Branch 選 main，資料夾 / (root)
  5. 按 Save

2.3 確認管線通了

等一到兩分鐘，開：

https://taipei-tagala-web.github.io/

因為還沒有 /zh-TW/ 資料夾，轉址後會看到 404——這是正常的。重點是網址有回應、不是「找不到伺服器」。

先確認管線通了再開始寫網頁。之後每次 push 都能立刻看到結果，這對 24 小時的專案是很大的心理支撐。

3用 Claude Code 生成網站

開 Claude Code，工作目錄指到 C:\Tagala-Web。CLAUDE.md 已經寫好放在根目錄，它會自動讀取，所以不必再花時間建立專案規範。

分工要清楚。版面長什麼樣、哪個區塊放哪、什麼時候拍板，這些你決定；把決定變成程式碼、灌內容、產生 hreflang 和 srcset 這類機械性工作交給它。最容易翻車的是把設計決策也丟出去，然後對著結果說「不太對，再改改」——那樣會來回十幾輪還定不下來。

3.1 設計拍板：只做中文首頁

請先讀 CLAUDE.md、assets/css/tokens.css，以及 content/ 底下三個 json。

接著只做繁體中文首頁 /zh-TW/index.html，以及 assets/css/main.css。
其他頁面先不要碰。

版面由上到下：

1. 頁首
   - 社徽在左，用 assets/logo/signature-bilingual.webp
     窄螢幕（768px 以下）改用 signature-compact.webp
   - 主導覽：關於我們／服務計畫／例會與活動／聯絡我們
   - 語言切換器：中文 / English / 日本語

2. Hero 區
   - 社名、一句話定位（site.json 的 club.tagline）
   - 例會時間與地點（site.json 的 meeting）

3. 近期例會
   - 從 events.json 取日期在今天之後的活動，最多 6 場
   - 每張卡片：16:9 banner、日期、活動類型標籤、標題、主講人、摘要
   - 圖片用 srcset 帶 600w 與 1200w，必須有 width height

4. 服務計畫摘要
   - service.json 的 facts 四張數據卡
   - service.json 的 mission 段落
   - 連到服務計畫頁的按鈕

5. 頁尾
   - 例會資訊、Facebook 連結
   - 國際扶輪與 3523 地區連結
   - 商標聲明與圖片聲明
   - 頁尾底色是皇室藍，社徽在深藍底上會失效，
     所以頁尾用文字社名，不要放社徽

技術要求：
- 只用 tokens.css 的 CSS 變數，不可寫死色碼
- 斷點只用 768px 和 1080px
- 要有「跳至主要內容」連結與鍵盤焦點外框
- 不引入任何框架或 CDN 套件

做完告訴我你做了哪些版面判斷，我要先看這一頁再決定下一步。

拿到之後只給一次大方向回饋。例如「Hero 太高，活動卡片要更緊湊」。改完就拍板，不要陷入微調。

3.2 中文版其餘四頁

中文首頁已定案。請以它為唯一樣板，產生中文版其餘四頁。
頁首與頁尾必須與首頁完全一致。

/zh-TW/about/index.html
  - 本社簡介、社名由來（site.json 的 club.nameOrigin）
  - 社旗意象（service.json 的 flagConcept，配 assets/brand/club-flag.webp）
  - 例會資訊完整版，包含來賓費用與報名方式

/zh-TW/service/index.html
  - service.json 的 mission
  - timeline 七個年度，做成時間軸
  - districtService 地區聯合公益
  - facts 數據卡
  - areasOfFocus 放在最後，標題註明為對應參考

/zh-TW/meetings/index.html
  - 近期例會：日期在今天之後，大卡片
  - 過往活動：日期在今天之前，時間倒序，小卡片
  - 例會固定資訊再出現一次（訪客最常找這個）

/zh-TW/contact/index.html
  - 例會地點與 Google Maps 嵌入
  - Facebook 專頁
  - 入社洽詢說明
  - 相關連結

每頁的 title 與 meta description 從 site.json 取。

3.3 英文版與日文版

請產生英文版與日文版，共十頁，與中文版一對一對應。

硬性要求：
1. URL 結構、版面、區塊順序與中文版完全相同
   /en/ 與 /ja/ 底下的五頁 slug 與 /zh-TW/ 一致
2. html lang 分別為 zh-Hant-TW、en、ja
3. 每頁三組 hreflang 加一組 x-default：
   zh-Hant 指向 /zh-TW/ 對應頁
   en 指向 /en/ 對應頁
   ja 指向 /ja/ 對應頁
   x-default 指向 /zh-TW/ 對應頁
   注意 hreflang 用 zh-Hant，不是 zh-TW
4. 語言切換器連到「當前這一頁」的其他語系，不是回首頁
5. 字型：中文頁只載 Noto Sans TC，日文頁只載 Noto Sans JP，
   英文頁只載 Open Sans。不可三種一起載
6. 日文版社名首次出現用 ruby 標記，讀音 タイペイ・タガラ
7. 圖片 alt 用對應語系
8. 英文版主標題與主導覽用 ALL CAPS；中日文版不用大寫，改用字重

翻譯內容全部從 json 取，不要自行重譯。
完成後執行 python3 tools/check-i18n.py 確認通過。

4上線前 QA

請做上線前檢查並修正：

1. 列出全站所有內部連結，標出失效的
2. 檢查 15 個內容頁的語言切換器是否都正確指向對應頁
3. 檢查所有 img 是否都有 alt、width、height、srcset
4. 產生 sitemap.xml，含全部三語系頁面
5. 產生 404.html，樣式與全站一致，提供三語系回首頁連結
6. 每頁補 Open Graph 標籤：og:title、og:description、og:image、og:locale
   og:locale 分別為 zh_TW、en_US、ja_JP
7. 每頁補 favicon 與 apple-touch-icon 連結
8. 檢查是否有寫死的色碼，有的話改用 tokens.css 變數

最後執行 python3 tools/check-i18n.py，確認通過。

5發布與確認

5.1 推上去

cd C:\Tagala-Web
git add .
git commit -m "完成三語系網站初版"
git push

約一分鐘後網站更新。以後每次修改都是這三行，沒有別的。

5.2 逐項確認

推壞了怎麼救。還沒 push、想丟掉本地改動：git checkout -- .　已經 push、想退回上一版：git revert HEAD 然後 git push。git revert 是新增一個抵銷的版本，不刪除歷史，比較安全。不要用 git reset --hard 加 --force。

6移交給正式站

這一步不在 24 小時內，等社內看過測試站確認後再做。

做法 A：請財務長把你加為協作者（建議）

財務長到 taipeitagala.github.io repo → Settings → Collaborators → Add people → 輸入 Taipei-Tagala-Web。你接受邀請後：

git remote add official https://github.com/taipeitagala/taipeitagala.github.io.git
git push official main

做法 B：檔案搬運

你的 repo 頁面 → 綠色 Code → Download ZIP → 解壓 → 財務長的 repo → Add file → Upload files → 全部拖進去 → Commit changes。可行，但每次更新都要重來。

7疑難排解

症狀原因解法
圖片全部破圖repo 名稱不是 帳號.github.io，網站被放在子目錄Settings → 最下方 Rename repository，改成 Taipei-Tagala-Web.github.io
某些檔案 404檔名或資料夾以底線開頭，被 Jekyll 忽略確認根目錄有 .nojekyll
push 被拒絕遠端有你本地沒有的變更git pull --rebase 後再 push
改了但網站沒變部署要一分鐘，或瀏覽器快取等一分鐘，然後 Ctrl+F5 強制重新整理
日文頁出現 □字型缺「蚋」字確認有載入 Noto Sans JP；仍不行就在日文頁改用片假名タガラ
中文字變方框沒載入 Noto Sans TC檢查字型連結與 lang 屬性拼寫
「無法辨識 git 詞彙」Git 沒裝，或裝完沒重開終端機先 winget install --id Git.Git -e，然後關掉 PowerShell 重開。gh 和 git 是兩個不同的程式，裝了一個不代表有另一個
「無法辨識 gh 詞彙」GitHub CLI 沒裝，或裝完沒重開終端機winget install --id GitHub.cli，然後重開 PowerShell
winget 本身無法辨識Windows 版本較舊或缺應用程式安裝程式從 Microsoft Store 安裝「應用程式安裝程式」，或直接用官網安裝檔
git 顯示整個檔案都被改過換行符差異確認做過 core.autocrlf true
中文路徑出現亂碼編碼問題確認 repo 在 C:\Tagala-Web\，路徑無中文與空格

不要把 repo 放在 OneDrive 或 Dropbox 同步資料夾裡。同步工具和 git 會互相打架，可能弄壞 .git 資料夾。

這個資料夾裡的東西全部會公開上網。GitHub Pages 會發布 repo 裡的每個檔案，包括這份手冊、README 和 json。這些沒有機密，但不要把社員名冊、財務資料放進來。
